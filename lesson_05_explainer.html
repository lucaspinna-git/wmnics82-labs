What Is Software? (Slide 8)

5.1.1 What Is Software?

A computer without software is like a car without fuel or an orchestra without sheet music. Software is a collection of coded instructions that tell computer hardware exactly what to do, when to do it, and how to do it. The computer's Operating System (OS) reads and executes these instructions.

Category 1 Foundation

System Software

Manages computer hardware, controls memory and storage, and provides a platform for applications to run. Without system software, the computer cannot start up.

Core Operating Systems & Drivers:
Microsoft Windows 11 Apple macOS Ubuntu Linux Device Drivers
⚙️ 5 Most Useful Windows System Applications Built-in Utilities
1. Task Manager taskmgr

Monitors live CPU, RAM, and disk usage in real time, and allows you to force close frozen or unresponsive programs.

2. System Information msinfo32

Displays detailed hardware specifications, BIOS/UEFI firmware version, processor details, and installed RAM.

3. Device Manager devmgmt.msc

Lists all connected physical hardware devices and lets technicians update, roll back, or troubleshoot device drivers.

4. Disk Management diskmgmt.msc

Displays internal hard drives, SSDs, and USB storage to initialise, format, and manage storage partitions.

5. Windows Terminal / Command Prompt wt / cmd

A text-based command-line interface used by technicians to run network diagnostics (like ping and ipconfig) and execute admin scripts.

🍏 Top System Utility for Mac: Activity Monitor macOS

The Mac equivalent of Task Manager. It displays real-time CPU, Memory, Energy, Disk, and Network usage, and allows technicians to inspect or force quit unresponsive Mac processes. Mac technicians also use Terminal for command-line diagnostics.

Category 2 User-Facing

Application Software

Programs designed to help end users perform specific tasks, such as writing a report, browsing a website, balancing a budget, or editing a photo.

📱 Common Application Software Descriptions End-User Tasks
1. Microsoft Word Word Processing

Used to write, format, edit, and print text documents such as letters, CVs, business proposals, and reports.

2. Google Chrome Web Browser

Used to access the World Wide Web, interact with cloud web applications, and display online multimedia securely over HTTPS.

3. Slack Team Collaboration

A communication platform used by business teams for real-time messaging, organised topic channels, and instant file sharing.

4. Adobe Photoshop Graphic Design

A professional raster image editor used to retouch photos, compose graphic artwork, and prepare digital visuals for marketing and print.

Top Tip

How to Quickly Access System Software on Windows

Technician Shortcuts

Support technicians need fast, reliable ways to launch system utilities without clicking through menus. Memorise these three essential methods:

🖱️ Right-Click Start (Win + X)

Right-click the Windows Start button (or press Win + X) to open the Power User Menu. Provides instant one-click access to Device Manager, Disk Management, Terminal, and Task Manager.

⌨️ Run Command (Win + R)

Press Win + R and type short command codes directly:
• taskmgr (Task Manager)
• msinfo32 (System Info)
• devmgmt.msc (Device Mgr)
• diskmgmt.msc (Disk Mgr)
• cmd or wt (Terminal)

⚡ Direct Shortcut (Ctrl + Shift + Esc)

Pressing Ctrl + Shift + Esc opens Task Manager instantly in a single keystroke, bypassing the Windows security lock screen even if an application is frozen.

Operating System Compatibility: Application software is written specifically for the target Operating System. A program compiled as a Windows executable file (.exe) cannot run natively on Apple macOS (.dmg or .app) without a compatibility layer or virtualisation.

Remote Assistance & Desktop Control (Slides 18–19)

5.2.3 Remote Assistance & Desktop Control

IT Support technicians cannot always be physically present at every user's desk. Remote Assistance Software allows an IT technician to see and control another computer across the network or internet as if they were sitting directly in front of it.

Built-in Windows Port 3389

Microsoft Remote Desktop (RDP)

Standard enterprise tool. Connects directly to Windows Pro and Enterprise editions on local networks or secure VPNs. Locks the host screen while in use.

Internet / Quick 6-Digit Code

Windows Quick Assist

Built into Windows 10 and 11. Designed for quick help sessions. The technician provides a 6-digit security code that the user enters to grant view or control access.

Cross-Platform Cloud Relay

5.3 Learning Outcome 5.3

Safely Managing Software & Licensing

Slides 21–25
5.3.1

Where Do You Find Software? (Slide 22)

5.3.1 Where Do You Find Software?

Decades ago, software was purchased in physical cardboard boxes on CDs or floppy disks. Today, almost all software is downloaded over the internet. However, downloading from the wrong place can infect a computer with spyware or ransomware.

Safe & Approved Sources

Curated App Stores & Official Sites

Always obtain software from verified platforms that vet applications for security and provide digitally signed installers:

  • Curated App Stores: Microsoft Store, Apple App Store, Google Play Store.
  • Official Vendor Websites: Downloading direct from the company (e.g. adobe.com or zoom.us) over secure HTTPS.
  • Company Software Portal: Enterprise repositories approved by your organisation's IT team.
Dangerous Sources

Rogue Portals & Unofficial Mirrors

Avoid third-party "free download" websites, torrent trackers, and unofficial forum links:

  • Adware & Bundlers: Fake download buttons that secretly install browser hijackers.
  • Cracked / Pirated Software: Often bundled with keyloggers or ransomware.
  • Outdated Repositories: Offer old versions that lack vital security patches.
5.3.2

Software Licensing Models (Slides 23–24)

5.3.2 Software Licensing Models

When you buy software, you do not own the code. You purchase a licence—a legal permit that defines how you can use it. Installing unlicensed software breaches copyright law and exposes organisations to severe legal fines.

Model 1

Proprietary / Commercial

Closed-source software owned by a company. Users pay a licence fee and cannot inspect or modify the underlying source code.

Examples: Windows 11, Adobe Photoshop
Model 2

EULA & Single Licence

The End User Licence Agreement sets terms of use. A standard single-user licence permits installation on only one designated device.

Rule: Must be agreed to before installation
Model 3

Site Licence / Volume

A blanket business contract allowing an organisation to deploy the software across hundreds of computers without buying individual keys.

Reduces administrative burden on IT teams
Model 4

Open Source (FOSS)

Source code is publicly available for anyone to view, modify, and redistribute freely (under licences like GPL, MIT, or Apache).

Examples: Linux kernel, LibreOffice, GIMP, VLC
Model 5

Software as a Service (SaaS)

Cloud subscription model. Users pay an ongoing monthly or annual fee. Software is always kept up to date automatically.

Examples: Microsoft 365, Google Workspace, Spotify
Model 6

Freeware vs Shareware

Freeware is free to use without paying, but source code is closed. Shareware offers a free trial period before requiring payment.

Examples: Adobe Acrobat Reader (Freeware), WinRAR (Shareware)
5.3.3

Installing & Safely Uninstalling Software (Slides 25–26)

5.3.3 Installing & Safely Uninstalling Software

Installing software adds files, libraries, and registry entries to the operating system. Over time, unused programs and manufacturer "bloatware" clutter storage, consume background RAM, and create security holes because they stop receiving patches.

🪟 Microsoft Windows Procedure
How to Install: Download installer (.exe or .msi), run setup, accept the EULA, pick install destination, and restart if prompted.
How to Safely Uninstall: Navigate to Settings > Apps > Installed apps. Find the program, click the three horizontal dots (...), and click Uninstall. Never just delete the shortcut icon off your desktop!
Stubborn Programs: If a program refuses to uninstall cleanly, technicians use dedicated uninstaller utilities like Revo Uninstaller to remove orphaned registry keys.
🍎 Apple macOS Procedure
How to Install: Open the downloaded disk image (.dmg), and drag the application bundle (.app) into the Applications folder.
How to Safely Uninstall: Open Finder > Applications, find the unwanted app icon, and drag it directly into the Trash can in the bottom right of the Dock. Then right-click and choose Empty Trash.
Second Thoughts: Before emptying the Trash, you can drag the application back to the Applications folder and it will continue to work normally.

5.4.3

ITIL Framework: Incidents vs Requests for Service

5.4.8.1 Understanding ITIL Ticket Types: Incident vs Request for Service

When users submit tickets to an IT service desk, technicians must immediately categorise the type of ticket. Treating a routine user request as an incident or treating an outage as a routine request causes chaos in the help desk queue:

ITIL Category 1 Service Interruption

Incident

"An Incident is defined as an unplanned interruption or reduction in quality of an IT service (a Service Interruption)."

Key Sign: Something that used to work is now broken, degraded, or halted. The primary objective is to restore normal operations as rapidly as possible.

Examples: Email server crashes, network printer offline, laptop blue screen of death, boardroom camera offline.
ITIL Category 2 Service Request

Request for Service (Service Request)

"A formal request from a user for something to be provided – for example, a request for information or advice; to reset a password; or to install a workstation for a new user."

Key Sign: Nothing has failed! It is a planned request for standard access, advice, new equipment, or pre-approved software installation. Handled via standard request fulfilment workflows.

Examples: Password reset for locked account, new starter PC setup, requesting a second monitor, installing a licensed copy of Microsoft Visio.
5.4.4

ITIL Incident Prioritisation Checklist & Priority Matrix

5.4.8.2 ITIL Incident Prioritisation Checklist

Based on ITIL Incident Management Standards

In ITIL-aligned service desks, technicians never assign priority by personal feelings or caller volume. Priority is strictly calculated by assessing Impact against Urgency:

1. Impact Assessment

Evaluates the extent of damage or disruption to the business:

  • User Count: How many users or departments are completely incapacitated?
  • Core Services: Is a revenue-generating service, customer portal, or payroll down?
  • Legal/Regulatory: Will this cause data loss or statutory regulatory fines?
2. Urgency Assessment

Evaluates the speed with which resolution is required:

  • Deadlines: Is there a strict banking cutoff or client pitch starting in minutes?
  • Delay Risk: Will waiting 30 minutes cause catastrophic business damage?
  • VIP / Executive: Are senior directors conducting critical stakeholder negotiations?
3. The Workaround Rule

A vital ITIL rule that prevents misallocated resources:

If an acceptable temporary workaround exists (e.g. printing on another machine down the hall or using Edge instead of Chrome), Urgency is downgraded, allowing technicians to focus first on blockers with no workaround.
The Standard ITIL Priority Matrix
Impact / Urgency High Urgency Medium Urgency Low Urgency
High Impact P1 - Critical P2 - High P3 - Medium
Medium Impact P2 - High P3 - Medium P3 - Medium
Low Impact P2 - High (VIP/Deadline) P4 - Low P4 - Low

5.4.8.3 Technical Domain Assessment: Hardware vs Software vs Networking

To route tickets to the correct resolver group, technicians must classify the root fault into one of three primary technical domains:

Hardware Domain

Involves physical devices and tangible electronics. If it can be kicked, unplugged, or physically swapped:

Cables • Docks • RAM • Power Supplies • Screens • Camera/Mic Hardware
Software Domain

Involves operating systems, desktop applications, services, and local files:

Windows Services • Print Spooler • Adware/PUPs • SQL Databases • Driver Bugs
Networking Domain

Involves communication paths between different machines and infrastructure:

Ethernet Switches • Wi-Fi APs • IP Subnets • DHCP • DNS • Default Gateway
5.4.5

The CompTIA 6-Step Troubleshooting Process Reference (Slides 28–35)

Gathering Information: The Five W's & Questioning Techniques

Step 1 Foundation

When users contact IT support, they are often frustrated, anxious, or unable to explain what has gone wrong in technical terms. Rather than jumping to conclusions or guessing, professional technicians follow the classical Five W's Framework to extract clear, factual details before touching a single system setting.

WHO? Scope
Who is affected?

Is it just one person at one desk, a whole team (such as Accounts), or every worker across the business? This establishes business impact immediately.

WHAT? Symptoms
What is happening?

What is the computer doing versus what did the user expect? What exact error message, warning dialogue, beep code, or unusual noise occurred?

WHEN? Timeline
When did it start?

Did it start 5 minutes ago, after a restart, or during lunchtime? Is it happening continuously or intermittently (only when performing a specific task)?

WHERE? Location
Where is the fault?

On a local laptop, in a specific boardroom, on the office Wi-Fi, on an on-premise server, or inside a cloud-hosted software application?

WHY? Urgency
Why is this urgent?

Why does this matter right now? Is payroll waiting to be run in 2 hours? Is an executive walking into a client pitch? This determines ITIL urgency.

🗣️
Open Questions: Discovery & Context
Start of Step 1

What they are: Questions that cannot be answered with a simple "Yes" or "No". They invite the user to explain and describe the scenario in their own words.

Where & When to use: Use them at the very start of the support interaction. Users often do not know technical terms, but they know what they were doing and what looked wrong. Listening to their story uncovers hidden symptoms without leading them into a false diagnosis.

Practical Real-World Examples:
  • "What were you doing on the computer when the error first popped up?"
  • "Can you describe what happens on your screen when you click 'Print'?"
  • "What changes or new cables have been plugged in recently?"
🎯
Closed Questions: Verification & Pinpointing
Testing Theories

What they are: Questions that demand a direct, factual "Yes" or "No" (or choosing between distinct options).

Where & When to use: Use them once you have heard the user's initial description. Closed questions help technicians confirm physical device states, test theories quickly, rule out basic mistakes, and keep non-technical users from drifting off topic.

Practical Real-World Examples:
  • "Is the small green power LED on the front of the monitor switched on?"
  • "Have you restarted your computer since the software update finished?"
  • "Can other colleagues sitting near you connect to the internet right now?"
Step 1 of 6 Slide 30

1. Identify the Problem

Gather as much accurate information as possible before touching any system settings:

  • Question the user: Ask open questions: "What were you doing when it failed?", "Are there any error messages or beep codes?"
  • Review diagnostic logs: Open Event Viewer (eventvwr.msc) and check recent entries in System and Application logs.
  • Identify recent changes: Were any software updates applied? Was new hardware plugged in? Did a power cut occur?
  • Back up critical data: Always protect the user's data before making any changes. Always have a way back!
Step 2 of 6 Slide 31

2. Establish a Theory of Probable Cause

Brainstorm what is most likely causing the issue, starting from the simplest explanation:

  • Question the obvious first: Is the power cable plugged in firmly? Is the wall socket switched on? Is the monitor turned on?
  • Check indicator lights & sounds: Look for power LEDs, drive activity lights, Num Lock, Caps Lock, or beeping fans.
  • Inspect performance gauges: Open Task Manager (taskmgr) to check for 100% disk usage, runaway CPU, or out-of-memory errors.
  • Prioritise your list: Rank theories from most likely to least likely.
Step 3 of 6 Slide 32

3. Test the Theory to Determine Cause

Isolate variables and test your ideas one at a time using diagnostic utilities:

  • Test one single variable: Never change multiple things at once; otherwise you won't know which action solved or broke the machine.
  • Inspect Device & Service status: Check devmgmt.msc for yellow warning triangles or inspect services.msc to see if a background service stopped.
  • If theory is disproved: Do not guess! Formulate a new theory or escalate the ticket to a senior engineer.
Step 4 of 6 Slide 33

4. Plan of Action & Implement the Fix

Create a clear, step-by-step procedure to fix the problem without causing collateral damage:

  • Write the action plan: List the exact sequence of steps required to implement the solution.
  • Identify business impact: Will applying the fix require rebooting a shared departmental server or restarting a router?
  • Obtain approval: Get managerial or change management sign-off if downtime is expected.
  • Execute the fix: Implement the solution methodically.
Step 5 of 6 Slide 34

5. Verify Full System Functionality

Confirm that the original issue is genuinely resolved and that nothing else was broken:

  • Test with the user: Have the person who raised the ticket log in, open their application, and confirm they can work normally.
  • Check adjacent systems: Make sure network connectivity, sound, and printing still function.
  • Implement preventative measures: Configure automatic updates, replace worn cables, or provide user training to prevent recurrence.
Step 6 of 6 Slide 35

6. Document Findings, Actions & Outcomes

Never close a ticket without creating a permanent record in the IT Knowledge Base:

  • Document the symptoms: Record what the user observed and any exact error codes.
  • Document the root cause: Clearly describe what actually failed (citing Event IDs or hardware fault codes).
  • Document the exact solution: List what steps and replacement components were used.
  • Why this matters: When another colleague encounters the same issue next month, they can fix it in minutes instead of starting from scratch!

INC0010489 • Staff Canteen Wi-Fi Video Dropouts P3 - Medium
Type & Domain: Incident • Domain: Networking (RF Interference & 2.4 GHz Contention).
Triage: Medium Impact (Several staff laptops buffering in canteen) + Medium Urgency (Lunchtime onboarding training video calls stuttering, but wired desks and offices unaffected) = P3 Medium.
Diagnostic Finding: Wi-Fi analyser showed intense RF noise bursts on 2.4 GHz Channel 6 coinciding exactly with canteen microwave usage; coated low-E safety glass walls further attenuated signal by 12 dB.
Fix & Prevention: Reconfigured Canteen Access Point with band steering to push all 802.11ax laptops onto the clean 5 GHz band (Channel 36 / 40 MHz width), completely bypassing 2.4 GHz microwave radiation.
Verify: Conducted 10-minute HD Teams test call during peak lunch reheating rush; packet loss dropped to 0% and throughput remained steady at 320 Mbps.
INC0010490 • Design Studio Dual 4K Display Flicker P2 - High
Type & Domain: Incident • Domain: Hardware (DisplayPort Physical Video Interface).
Triage: Medium Impact (Lead designer workstation) + High Urgency (National client print catalogue proofing deadline in 45 minutes) = P2 High.
Diagnostic Finding: Task Manager showed GPU load 8% and normal temperatures (ruling out GPU crash); Device Manager showed RTX A2000 graphics card healthy. Physical inspection revealed DisplayPort cable pins pinched when motorised sit-stand desk was elevated.
Fix & Prevention: Replaced damaged DisplayPort cable with a heavy-duty 2-metre VESA-certified DisplayPort 1.4 cable, adding flexible spiral cable spine to provide slack for desk height travel.
Verify: Both 4K Dell UltraSharp monitors locked at 3840x2160 @ 60Hz with zero black-screen dropouts or colour artifacts. Lead designer signed off proof.
