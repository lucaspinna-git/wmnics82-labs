What is Coding?

Slide 9 – 18 • Languages, Syntax, Compilers, Interpreters & Queries

9.1.1 Coding Overview

Analogy

Coding is writing step-by-step instructions that tell a computer processor exactly what to do.

Real-World Analogy: The Cake Recipe

Think of computer code like a baking recipe. A recipe tells a baker the exact ingredients to fetch (inputs), how long to bake them (processing), and what cake comes out of the oven (output). If you miss a step or skip an ingredient, the cake fails. Computers follow your instructions literally in the exact order written.

9.1.1b Strict Syntax Rules

Core Concept

A programming language gives programmers a structured vocabulary to talk to hardware. Unlike spoken English, every language follows strict syntax (computer grammar and punctuation rules).

print("Welcome to IT Support!") Valid Syntax
print("Welcome to IT Support! Syntax Error (Missing ") )
Top Tip: A computer cannot guess what you meant. Even a single missing quote mark or bracket will stop the program from running.

9.1.5 Query Languages (SQL)

Lesson 8 Link

Not all code builds apps or games. Query languages specialise in talking to databases to search, add, update, or remove records. The most common example is Structured Query Language (SQL), which you practised in Lesson 8. 

SELECT * FROM documents
WHERE content LIKE '%video games%'
   OR content LIKE '%coding%';
How Queries Help IT Support:

• Check how many laptops remain in stock.

• Find all support tickets raised this week.

• Search large catalogues like film websites (IMDb) in milliseconds.

9.2.1 Define What the Program Should Do

House Analogy
Slide 21 Analogy: Why Follow a House Plan?

Builders do not start laying bricks without a blueprint first. If they did, doors might not fit or walls could collapse. Good software engineers plan their program on paper before writing a single line of code.

1. Purpose What will the software do?
2. Hardware How will it use CPU, RAM, or sensors?
3. Interaction How will users type, tap, or click?
4. Display What will appear on the screen?

9.3.1 What is a Variable? & Data Types

Slides 32 – 33 • Understand how named RAM boxes hold different data formats — and test the “Type Trap” below.

Interactive Lab
Slide 32 Analogy: The Labelled Game Score Box

A variable is like a labelled storage box inside RAM that holds a value. When a player collects coins in a video game, the number inside the score box changes, while the box label stays the same. A constant (like VAT_RATE = 0.20) is a locked box that never changes while the program runs.

Integer Whole numbers 4, 33, -256
Float Standard decimals 28.4, 231.28, 5.0
Double High-precision decimals 201.568793
Fixed-Point Exact money digits £1.99, £456.78
Character (char) Single letter or symbol 'A', '%', '6'
String (str) Multiple characters/text "Hello World"
Boolean (bool) True or False switch True, False
Array Ordered list in one variable {"Maths", "Art"}

9.3.2 Arrays & Zero-Based Indexing

Module 10.3.7

Instead of creating dozens of separate variables (subject1, subject2), an Array stores a whole list of related items in one container. Most programming languages start counting array positions at 0 instead of 1.

9.3.3 Boolean Operators: AND, OR, XOR & NOT

Slides 34 – 35

Boolean operators combine True and False checks to help programs make smart decisions. Here is the café drink analogy from Slide 35:

AND

Both must be true.

“You only get a free pastry if you order Tea AND Coffee together.”

OR

Either one (or both) is true.

“You get a hot drink if you order Tea OR Coffee (or both).”

XOR (Exclusive OR)

One OR the other, never both.

“Pick Tea or Coffee — mixing both in one cup is wrong (False)!”

NOT

Flips True to False (or vice versa).

“Drink Coffee if the cup is NOT Tea.”

9.4.1 Program Flow & Branching

Slides 40 & 42

Program flow is the order a computer runs instructions: top to bottom, one line after another (sequential flow), unless a branch or loop changes path.

// Slide 42 Pseudocode Branching
IF hero finds hidden key THEN
Reveal treasure room
ELSE
Keep door locked
ENDIF

9.4.1b Code Documentation (Comments)

Slide 41

Large programs contain thousands of lines. Programmers write comments as plain-English sticky notes in the code so teammates understand what each section does. The computer completely ignores comments when running.

# Comment Python / Bash
// Comment JavaScript / C++ / C#
' Comment / Rem Visual Basic / Batch
/* Multi-line */ C / CSS / SQL / Java

Functions & Keeping Code DRY (“Don’t Repeat Yourself”)

Slide 44

A function is a named mini-program that performs one specific job (for example, print("Hello World!")). Think of a function like a saved button on a coffee machine: you write the recipe once, then press the button whenever you need a cup without rebuilding the steps every time.

9.4.4 Troubleshooting & Debugging

Slide 46

Programmers are human, so typing thousands of lines leads to mistakes. Running software to track down and fix errors is called debugging.

Syntax Error Broken grammar rule (like a missing bracket). Caught immediately before running.
Logic Error Code runs without crashing, but gives the wrong answer (like using + instead of -).
History Bite: Where Did the Word “Bug” Come From?

In 1947, computer pioneer Grace Hopper and her team at Harvard found a real moth trapped inside a relay of the Harvard Mark II computer, stopping it from working. They taped the moth into their logbook and wrote: “First actual case of bug being found.”

9.4.5 Careers in Coding & Takeaways

Module 10.5

Coding skills open doors across IT support, web development, automation, and software engineering:

Junior Software Developer Writes, tests, and debugs applications using Python, JavaScript, or C#.
IT Automation & Scripting Technician Uses short scripts (PowerShell, Bash, Python) to automate repetitive helpdesk fixes and software updates.
QA / Software Tester Designs test cases to catch syntax, logic, and edge-case bugs before software reaches users.
